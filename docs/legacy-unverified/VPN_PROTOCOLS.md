# VPN_PROTOCOLS.md
## بروتوكولات VPN المدعومة والمعايير الهندسية

### 1. بروتوكول WireGuard (البروتوكول الأساسي)
يُعتبر WireGuard أحدث بروتوكولات الـ VPN مفتوحة المصدر، ويتميز بالسرعة الفائقة، استهلاك البطارية المنخفض، وبساطة التصميم التشفيري.

* **بروتوكول التفاوض والمصافحة:** Noise Protocol Framework (نمط `Noise_IKpsk2_25519_ChaChaPoly_BLAKE2s`).
* **خوارزميات التشفير المعتمدة:**
  * تبادل المفاتيح: Curve25519 (ECDH) بطول 32 بايت.
  * التشفير المتناظر والمصادقة: ChaCha20-Poly1305 AEAD.
  * التجزئة وتوليد المفاتيح: BLAKE2s مع KDF2 / KDF3.
  * الختم الزمني: TAI64N (12 بايت) لمنع هجمات إعادة الإرسال (Replay Attacks).
* **إدارة الاتصال والاستقرار:**
  * دورة تحديث المفاتيح (Rekeying): إعادة التفاوض كل ساعتين أو بعد نقل $2^{64}$ حزمة.
  * الحفاظ على الاتصال (Persistent Keepalive): إرسال حزمة Keepalive كل 25 ثانية لتجاوز مهلات NAT والـ Firewall.
  * حجم وحدة النقل الأقصى (MTU): ضبط MTU تلقائي على 1280 إلى 1420 بايت لمنع تجزئة حزم UDP.

---

### 2. بروتوكول Xray / VLESS (محرك تجاوز الرقابة والـ DPI)
تم تصميمه للتعامل مع الشبكات التي تفرض رقابة شديدة وحجبًا لحزم UDP أو اتصالات VPN القياسية.

* **بروتوكول النقل (Transport):**
  * **VLESS over TLS / REALITY:** يحاكي مصافحة HTTPS الطبيعية مع خوادم حقيقية معتمدة، مما يمنع جدران الحماية من كشف طبيعة الاتصال.
  * **WebSocket / gRPC Fallback:** إمكانية تمرير الحزم عبر اتصالات HTTP/2 أو WebSocket للشبكات التي تسمح بالمنافذ 80 و 443 فقط.
* **التعامل مع حجب UDP:**
  * دعم توجيه UDP-over-TCP عند قيام مزود الخدمة بحظر حزم UDP بالكامل.
* **التوافق المعماري:**
  * إمكانية العمل إما عبر مكتبة النواة (Go Core / C-Shared .so) أو عبر عميل SOCKS5/HTTP محمي داخلياً ومرتبط بواجهة TUN.

---

### 3. معيار OpenVPN (الدراسة والجدوى)
* **المزايا:** يدعم TCP/UDP وتوافق عريض مع كافة البنى التحتية القديمة.
* **التقييم الهندسي:** يتطلب حجم مكتبات ثنائية كبيرة (Native C++ / OpenSSL) تزيد من حجم الـ APK بأكثر من 15 ميجابايت وتستهلك طاقة بطارية أعلى من WireGuard بنسبة تصل إلى 25%.
* **القرار المعماري:** تم إعطاء الأولوية القصوى لـ WireGuard كبروتوكول افتراضي سريع وخفيف، وXray للشبكات المحجوبة، مع إمكانية استيراد ملفات `.ovpn` عند دمج محرك OpenVPN مستقبلاً دون تضخيم التطبيق في المرحلة الحالية.

---

### 4. آلية الاختيار الذكي للبروتوكول (Auto-Protocol Selection)
يطبق محرك `VpnEngineManager` خوارزمية ذكية لاختيار البروتوكول الأنسب وفق الخطوات التالية:
1. فحص الاتصال الأولي عبر WireGuard (الأسرع والأقل تأخيراً).
2. قياس زمن الاستجابة والمصافحة الأولية (Handshake Timeout: 4 ثوانٍ).
3. في حال فشل المصافحة أو حظر منافذ UDP من قبل مزود الخدمة:
   - تصنيف الخطأ كـ `UDP_BLOCKED` أو `HANDSHAKE_TIMEOUT`.
   - التبديل التلقائي إلى بروتوكول Xray / TLS المقنع.
4. حفظ النتيجة والبروتوكول الناجح في التخزين المحلي للشبكة الحالية (Wi-Fi SSID أو Cellular Carrier) لتسريع الاتصالات اللاحقة مباشرة دون محاولات فاشلة.
